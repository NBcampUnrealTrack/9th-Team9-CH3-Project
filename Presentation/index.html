FEATURE 01

인벤토리 및 상점 — 저장과 네트워크 상태를 분리

01 RequestPurchase(ItemId) — 상점 항목 선택 02 TryPurchaseConsumable — 태그·중복·가격·잔액 확인 03 Money 차감 + OwnedConsumables 등록 + SaveData 04 RefreshShopUI — 상점·보유 목록·요약 재구축 05 스테이지 진입 시 Server_SubmitLoadout → 복제

플레이어 경험

구매 직후 보유 목록과 재화가 갱신되고, 선택한 로드아웃이 스테이지에서 사용됨

역할 경계

구매는 로컬 SaveGame. 서버는 제출된 장착 목록의 개수·태그·중복·카탈로그를 검증

서버 권한 소유 프로필은 없음. 로컬 SaveGame은 조작 방지 수단이 아님.

TryPurchaseConsumableParcelGameInstance.cpp
if (ItemData->Price < 0) return false;
if (HasOwnedConsumable(ItemTag)) return false;
if (Money < ItemData->Price) return false;

Money -= ItemData->Price;
OwnedConsumables.Add(ItemTag);
SaveData();

FItemData는 ItemTag·Price·Effects를 정의. 스테이지의 UInventoryComponent::Items는 RepNotify로 UI에 전달.

FEATURE 03

DeliveryBox와 캐릭터의 물리 충돌 처리

이전 · 프리셋 의존

  • 상자 Root는 UBoxComponent
  • PhysicsBody 프로필과 Simulate Physics만 설정
  • Pawn 응답과 Collision Enabled를 코드에서 명시하지 않음
  • Character Blueprint의 캡슐 설정과 조합에 따라 결과가 달라질 여지
목적 바닥의 상자가 캐릭터를 통과하지 않도록 양쪽 채널을 대칭 설정
바닥: QueryAndPhysics→운반: NoCollision→드롭: 물리·충돌 복원

현재 · 코드로 명시

// DeliveryBox
CollisionComponent->SetCollisionEnabled(
    ECollisionEnabled::QueryAndPhysics);
CollisionComponent->SetCollisionResponseToChannel(
    ECC_Pawn, ECR_Block);

// ParcelCharacter Capsule
GetCapsuleComponent()->SetCollisionResponseToChannel(
    ECC_PhysicsBody, ECR_Block);
상태 전이 Attach 때 Actor collision/physics를 끄고, Detach 뒤 QueryAndPhysics·simulation·hit notify를 복원
네트워크상자 이동 복제 활성화OnRep_CarriedBox가 각 머신의 Attach/Detach 충돌 상태 적용Blueprint preset [에디터 확인 필요]

TROUBLESHOOTING 01

호스트 네임플레이트 — 복제가 아니라 로컬 가시성 문제

오류 현상 · 원인 파악

  • 클라이언트 화면에서는 호스트 이름이 보임
  • 호스트 자신의 화면에서만 호스트 이름이 숨겨짐
  • 따라서 PlayerState 이름 복제 자체는 동작
  • 현재 함수가 모든 로컬 제어 Pawn을 명시적으로 숨김
호스트만 보이는 이유 Listen Server 호스트는 Authority이면서 IsLocallyControlled()==true
원인 파악→로컬 가시성 처리 정리→양쪽 화면 정상 표시

기존 원인 코드 · 해결 결과

if (IsLocallyControlled())
{
    NameplateWidgetComp->SetVisibility(false);
    NameplateWidgetComp->SetHiddenInGame(true);
    return;
}
해결 결과 로컬 캐릭터도 표시 대상에 포함되어 호스트와 클라이언트 화면에서 네임플레이트가 정상 표시됨
해결 확인Host→Host 정상Host↔Client 정상이름 복제 경로 유지해결 완료

TROUBLESHOOTING 02

C++ UFUNCTION과 Blueprint 노드 버전이 어긋난 문제

오류 현상 · 원인

  • WBP_SkinCustomization 로드 시 기존 Apply Skin / Equip Skin 노드 핀을 찾지 못함
  • 현재 C++에는 두 함수가 BlueprintCallable로 존재
  • Editor DLL은 7월 22일, 관련 헤더는 7월 23일 수정본
  • 즉 Blueprint가 읽는 Reflection 정보가 현재 소스보다 오래됨
원인 소스·생성 코드·로드된 Editor 모듈의 버전 불일치
Editor 종료→Parcel_KnightEditor 빌드→Refresh All Nodes→Compile / Save

검증 · 해결 기준

// 현재 소스
UFUNCTION(BlueprintCallable)
void EquipSkin(FGameplayTag SkinTag);

UFUNCTION(BlueprintCallable)
void ApplySkin(FGameplayTag SkinTag);
완료 조건 에디터 재시작 뒤 두 노드의 Target·Skin Tag 핀이 복구되고 Blueprint 컴파일 오류가 없어야 함
확인 결과UE 5.5 읽기 전용 로드에서 불일치 재현원본 에셋은 수정하지 않음[Blueprint 노드 캡처 및 실행 흐름 확인 필요]

TROUBLESHOOTING 03

DeliveryBox와 캐릭터의 물리 충돌이 일관되지 않던 문제

오류 현상 · 원인 파악

  • 바닥 상자가 캐릭터를 통과하거나 반응이 일정하지 않음
  • Root는 CollisionComponent, Mesh는 NoCollision
  • 이전 생성자는 PhysicsBody 프리셋에만 의존
  • Character Capsule의 PhysicsBody 응답도 코드에 없었음
검증 Git 594f37c 직전/현재 생성자와 Carry의 Attach/Detach 상태 비교
잘못된 설정 확인→Pawn ↔ PhysicsBody→Attach / Detach→Block 적용

해결 코드 · 개선 범위

  • 상자: QueryAndPhysics + Pawn Block
  • 캡슐: Pawn profile + PhysicsBody Block
  • 운반 중: Actor collision·simulation 비활성
  • 드롭 후: collision·simulation·hit notify 복원
  • 던진 당사자는 0.5초 동안만 임시 무시
개선 결과 코드상 바닥/운반/드롭 상태가 분리됨. 실제 양쪽 화면 결과는 PIE 검증 필요
재검증Listen Server + Client에서 밀기·들기·놓기·던지기Zone overlap·배송 판정 회귀 확인BP_DeliveryBox preset [에디터 확인 필요]

TECHNICAL ISSUE 01

서버와 클라이언트의 역할 분리

문제 상황

상태 위조 방지

점수·체력·배송 상태·Carry 상태를 클라이언트가 직접 바꾸면 모든 화면의 결과가 달라짐

TeamScore · HP · BoxStateTags · CarriedBox
어려웠던 상황

Listen Server

호스트는 서버와 로컬 플레이어 역할을 동시에 수행해 OnRep만 기다리면 로컬 표현이 빠질 수 있음

HasAuthority + IsLocallyControlled
판단 기준

판정과 표현 분리

게임 규칙은 서버, 지속 상태는 Replication, 소유자 알림은 Client RPC, 순간 표현은 Multicast

intent → validate → mutate → replicate

최종 접근 · 서버

DeliveryZone, HealthComponent, TeamScoreComponent가 Authority를 확인한 뒤 상태 변경.

최종 접근 · 상태

BoxStateTags, HP, Score, Inventory, CarriedBox를 Replicated/RepNotify로 동기화.

최종 접근 · 표현

OnRep·delegate·Client/Multicast RPC로 HUD, 사운드, FX를 갱신.
